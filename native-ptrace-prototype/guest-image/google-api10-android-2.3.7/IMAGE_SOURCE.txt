## Rootless extracted guest staging

The original `system.img` is raw ext4 (superblock magic `53 ef`, 4 KiB blocks). It was read with userspace `debugfs` only; no mount and no host root were used. The extracted `system-tree/` contains 35 directories, 413 regular files and 53 symlinks (about 104 MiB). `debugfs rdump` emitted 448 `Operation not permitted while changing ownership` warnings because extraction intentionally ran unprivileged. File contents and symlink targets were extracted; host uid/gid are not the original image metadata. The original `system.img` remains untouched and authoritative for guest metadata.

`ramdisk-root/` is the complete userspace extraction of the original gzip/newc CPIO. `guest-root-staging/` combines that ramdisk root with the extracted matching `/system` tree using a relative `/system -> ../system-tree` link; this is staging only, not a host mount or guest boot. `tests/verify_google_api10_guest.sh` validates archive/image hashes, original init identity, CPIO symlinks, guest-root layout, and the dynamic `/system/bin/app_process` interpreter requirement.

The original ramdisk `/init` is static ELF32/ARM. `/system/bin/app_process` is ELF32/ARM dynamic, requests `/system/bin/linker`, and is launched from `init.rc` as Zygote with `--start-system-server`. The original init has not been executed. The current isolated supervisor is a strict single-process probe, with `/mnt`-only path mapping and no fork/vfork/clone tracing; unknown calls are canceled. It lacks safe guest-root path/symlink mediation, Android property/device semantics, uid/gid virtualization and dynamic child execution. No new APK was built; the earlier v0.1.1 probe APK is unchanged and still awaits on-device retest.
